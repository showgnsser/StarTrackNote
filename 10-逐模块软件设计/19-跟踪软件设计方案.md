# 跟踪软件设计方案

## 软件接口记号

本文使用以下记号描述软件接口、物理量和时间范围。

| 记号 | 含义 |
|---|---|
| $Z=I+jQ$ | 一条复相关结果，$I$为同相分量，$Q$为正交分量 |
| PDI历元 | 从1开始递增的1 ms预检测积分编号 |
| $[n_0,n_1]$ | 包含首尾历元的闭区间 |
| `ready` | 当前历元刚好形成一个完整观察结果 |
| `valid` | 已形成的结果通过该模块的数值和质量检查 |
| `complete` | 当前PDI的时间轴、相关值和命令确认均允许后级使用 |
| chip | 码相位、码间距和码误差单位 |
| cycle | 载波相位单位，1 cycle等于一个完整载波周期 |
| Hz | 载波频率或频率误差单位 |
| Hz/s | 载波频率变化率单位 |

`ready`和`valid`必须分开解释。`ready=false`表示观察窗口尚未成熟；`ready=true, valid=false`表示窗口已经成熟，但结果没有通过门控。数值0不能代替“尚未成熟”或“无效”。

本文所称PDI（Pre-Detection Integration，预检测积分）均指硬件形成的1 ms复相关结果，不是软件日志的20 ms输出周期。

## 1 设计范围

软件跟踪从接收一条1 ms PDI开始，到生成下一条硬件控制字结束。软件处理范围包括：

1. 检查PDI时间轴、错误标志和命令确认；
2. 将硬件相关结果转换到统一的软件数值域；
3. 选择默认闭环分量并统一固定载波相位；
4. 完成数据bit、覆盖码和导频二次码同步；
5. 将连续1 ms结果组合成当前策略需要的相干积分和非相干积累；
6. 形成载波频率、载波相位和码误差观察；
7. 更新载波FLL/PLL和载波辅助DLL；
8. 形成C/N0、频率、相位、码环和动态监测结果；
9. 根据监测证据选择十一种跟踪策略；
10. 生成下一历元的载波NCO、码NCO、抽头间距和相关支路控制字；
11. 输出当前历元的观察、控制、同步、状态和诊断结果。

软件不访问原始ADC I/Q样点，也不重新完成载波混频、本地码生成或逐样点相关。ADC至1 ms PDI之间的处理由[[09-逐模块定点化/18-跟踪逻辑定点化设计方案|跟踪逻辑定点化设计方案]]规定。

### 1.1 软件输入

软件每1 ms接收一条PDI，内容包括：

- PDI历元号和本历元实际使用的硬件命令号；
- PDI首样点编号和实际积分样点数；
- 本历元使用的载波NCO步进与首样点载波相位；
- 主码周期号、1 ms片段号和每主码片段数；
- 首段不完整、样点缺口、相关溢出和命令迟到标志；
- 当前资源池有效分量、有效副本和有效码抽头的复相关结果。

外部符号辅助是可选输入。启用时，每条PDI同时提供与该PDI严格对齐的$+1/-1$导航符号及其有效标志；未启用时符号为未知状态，软件不得假定数据正负号。

### 1.2 软件输出

软件每1 ms输出两类结果。

第一类是供后续软件和日志使用的当前历元结果，包括：

- 载波频率、载波相位和码误差观察；
- 数据bit或导频二次码同步状态；
- C/N0和环路稳定性监测结果；
- 载波环、码环和当前跟踪状态；
- 当前PDI和命令时间轴是否正常；
- 哪些观察在本历元真正进入闭环控制。

第二类是写回硬件的下一历元控制字，包括：

- 载波NCO频率控制字；
- 码NCO频率控制字；
- E/L与VE/VL抽头间距；
- 分量、副本和VE/VL使能；
- 仅在首次装载或明确重捕时使用的载波相位与码相位装载量；
- 单调递增的命令号和目标生效历元。

## 2 跟踪软件数据链总览

每条1 ms PDI按照六个阶段顺序处理。前一阶段可以使本历元数据失效或清理不连续窗口，但不能跳过后续安全处理。

![[90-附件/图STSW-00_跟踪软件数据链总览_v01.svg]]

图中从左到右给出一条1 ms PDI的完整软件主线。每个模块把本历元形成的观察、控制、同步、监测和状态写入软件结果，最后与下一历元硬件控制字一起输出。

| 阶段 | 输入 | 处理过程 | 主要输出 |
|---:|---|---|---|
| 1 | 当前PDI、预期历元、预期命令号 | 检查时间轴与硬件错误，确认此前等待提交的状态或码控制事件 | PDI正常标志、命令正常标志、控制事件确认结果 |
| 2 | 硬件相关、NCO参考、信号目录 | 转换相关值和物理NCO参考，选择默认闭环分量并统一固定相位 | 统一软件PDI |
| 3 | 软件PDI、可选辅助符号 | 执行同步、符号擦除、积分、C/N0估计和载波/码观察 | 同步、频率、相位、码误差和质量观察 |
| 4 | 当前观察、上一历元环路状态 | 将观察换算到当前控制时刻，更新载波环和载波辅助码环 | 载波频率、频率变化率、相位控制量和码率控制量 |
| 5 | 环路监测、同步、C/N0和辅助有效性 | 根据迟滞和连续确认选择下一跟踪策略 | 当前状态和待确认目标状态 |
| 6 | 当前状态、环路输出和相关策略 | 组合下一历元NCO、抽头和相关支路控制字 | 下一历元硬件控制字 |

完整处理链为：

```text
1 ms PDI
  -> 时间轴与命令确认
  -> 数值转换与默认分量统一
  -> 同步与符号擦除
  -> 相干积分与非相干积累
  -> 载波、码和C/N0观察
  -> 载波环与载波辅助码环
  -> 频率、相位、码和动态监测
  -> 跟踪状态选择
  -> 下一历元硬件控制字
```

### 2.1 软件模块分层

| 层级 | 输入 | 输出 | 职责 |
|---|---|---|---|
| 输入转换 | 硬件PDI | 统一软件PDI | 转换数值与时间参考，不做测量 |
| 同步 | 原始软件PDI | 同步状态、符号已处理PDI | 确定bit或二次码边界，统一符号 |
| 积分 | 连续1 ms PDI | 相干块或功率积累 | 按当前策略组织观察数据 |
| 观察器 | PDI或积分结果 | 频率、相位、码误差、C/N0 | 从相关结果提取物理测量 |
| 环路 | 有效观察、历史控制状态 | 载波和码率控制状态 | 完成预测、校正与状态记忆 |
| Monitor | 多次观察和环路结果 | 稳定、动态和锁定证据 | 汇总证据，不生成NCO控制 |
| 状态机 | Monitor、同步、C/N0 | 当前策略和待确认策略 | 只选择策略，不实现鉴别器 |
| 命令组合 | 状态策略、环路输出 | 下一历元硬件控制字 | 把软件控制量转换为硬件接口 |

观察器、环路、Monitor和状态机的职责必须分开：

- 观察器只回答“从当前数据测到了什么”；
- 环路只回答“根据测量，下一步控制量是多少”；
- Monitor只回答“测量与控制是否已经稳定”；
- 状态机只回答“下一阶段应采用哪套观察与控制策略”；
- 日志只记录事实，不能反馈闭环。

### 2.2 每历元结果的有效性

软件每1 ms先建立一份安全默认结果。某个模块只有在本历元收齐完整窗口时才置`ready=true`，只有通过该模块的数值和质量检查时才置`valid=true`。因此同一历元可能出现以下组合：

- 频率观察成熟并进入FLL；
- 相位观察成熟但当前状态禁止进入PLL；
- 码观察仍在积累，DLL只保持或预测；
- 同步仍在搜索，长相干积分尚未开放；
- C/N0沿用最近的新鲜结果，但本历元没有发布新值。

观察是否进入环路必须另行记录。`valid=true`只表示测量通过观察器门控，不等于该测量一定被当前状态用于控制。

### 2.3 命令确认时序

设当前输入为PDI $n$，处理顺序为：

1. PDI $n$报告它实际使用的命令号；
2. 软件根据命令号确认此前等待提交的状态或码控制事件；
3. 软件处理PDI $n$，更新观察、环路、监测和状态候选；
4. 软件生成目标历元为$n+1$的新控制字；
5. 后续PDI回报新的命令号后，相应状态或控制事件才算正式提交。

因此“软件决定切换”和“硬件已经按新策略运行”是两个不同时间点。状态机先产生待确认目标，只有后续PDI证明新控制字已经生效，状态切换才完成。

## 3 PDI输入转换与默认环路分量统一

### 3.1 模块功能

本模块把硬件1 ms PDI转换为后续同步、积分和观察器共同使用的软件PDI。它完成以下处理：

1. 将硬件相关整数无损转换到软件浮点数值域；
2. 将模$2^{32}$载波步进解释为有符号物理频率；
3. 将PDI首样点载波相位推进到PDI中心；
4. 原样传递历元、命令、样点和主码分段时间轴；
5. 选择当前信号的默认闭环分量；
6. 消除不同分量定义中的固定正交载波相位；
7. 汇总硬件错误和软件时间轴检查，形成PDI完整性。

![[90-附件/图STSW-01_PDI输入转换与环路分量统一_v01.svg]]

图中从左到右给出一条PDI的输入转换顺序。先检查历元与命令，再换算NCO物理参考、转换复相关、选择默认环路分量、统一五抽头固定相位，最后合并错误标志形成完整软件PDI。默认环路分量只建立便于闭环使用的五抽头结果，不删除或覆盖完整相关矩阵。

本模块不执行bit或二次码同步，不做长积分，不形成频率、相位或码误差观察，也不更新载波环、码环、Monitor或状态机。

### 3.2 输入

| 输入 | 单位或格式 | 作用 |
|---|---:|---|
| PDI历元号 | 无 | 检查1 ms处理时间轴是否连续 |
| 实际命令号 | 无 | 确认硬件是否使用了软件预期的控制字 |
| 首样点编号 | sample | 保留绝对输入时间参考 |
| 积分样点数 | sample | 确定PDI中心时刻 |
| 载波NCO步进 | u32圆环整数 | 换算本历元实际NCO频率 |
| 首样点载波相位 | u32圆环整数 | 推进得到PDI中心相位 |
| 主码周期号与1 ms片段号 | 无 | 供E1、B1C完整主码组合和同步使用 |
| 不完整、缺口、溢出、迟到标志 | 布尔 | 判断当前PDI能否作为有效观察证据 |
| 相关矩阵 | s18或s20复整数 | 当前资源池有效分量、副本和抽头的1 ms复相关 |
| 信号目录 | 固定配置 | 给出默认环路分量和固定载波相位 |

### 3.3 输出

| 输出 | 单位 | 含义 |
|---|---:|---|
| PDI历元和命令号 | 无 | 与输入保持一致 |
| 首样点编号和积分样点数 | sample | 与输入保持一致 |
| 主码周期号和1 ms片段号 | 无 | 与输入保持一致 |
| 载波NCO频率 | Hz | 当前PDI实际采用的载波NCO频率 |
| PDI中心载波相位 | cycle | 与当前复相关中心时刻对应的NCO相位 |
| 完整相关矩阵 | 浮点复数 | 全部有效分量、副本和抽头，数值尺度不变 |
| 默认环路五抽头 | 浮点复数 | 已选择默认分量并消除固定载波相位 |
| PDI完整性 | 布尔 | 是否允许后续观察器把本PDI作为有效证据 |

### 3.4 载波NCO频率换算

硬件载波步进是模$2^{32}$的u32位字。软件先按32 bit二补码解释为有符号整数$K_c$：

$$
K_c=
\begin{cases}
R_c, & R_c<2^{31} \\
R_c-2^{32}, & R_c\ge 2^{31}
\end{cases}
$$

式中，$R_c$表示载波步进的u32原始整数，$K_c$表示按有符号频率解释后的整数步进。

物理NCO频率为：

$$
f_{NCO}=\frac{K_c}{2^{32}}f_s
$$

式中，$f_{NCO}$表示当前PDI使用的载波NCO频率，单位Hz；$f_s$表示当前信号的固定采样率，单位sample/s。

该换算使用PDI记录的实际NCO步进，不使用软件刚计算出的下一控制字。这样后续观察始终以“硬件真正使用了什么”为参考，而不是以“软件希望硬件使用什么”为参考。

### 3.5 PDI中心载波相位

硬件记录的是PDI首样点使用的载波相位。观察器使用PDI中心作为统一时间参考，因此先计算中心样点偏移：

$$
d_c=\frac{N-1}{2}
$$

式中，$N$表示本PDI实际积分样点数，$d_c$表示从首样点到PDI中心的样点间隔；$N=0$时令$d_c=0$。

PDI中心载波相位为：

$$
\phi_{center}=\operatorname{frac}\left(
\frac{R_\phi}{2^{32}}+d_c\frac{K_c}{2^{32}}
\right)
$$

式中，$R_\phi$表示PDI首样点载波相位的u32原始整数；`frac`表示将结果回绕到$[0,1)$ cycle。

中心相位必须与本PDI的复相关、NCO频率和历元一起传给后续相位恢复与频率重定时。不能把首样点相位直接作为整条PDI的相位参考。

### 3.6 相关值转换

资源池0、2和3输出s18复相关，资源池1输出s20复相关。软件将每个有效$I/Q$整数直接转换为浮点数：

$$
I_{sw}=I_{hw},\qquad Q_{sw}=Q_{hw}
$$

这里不除以积分样点数，不执行幅度归一化，也不补偿前端增益。整数到浮点的转换不改变相关值之间的幅度比例和复相位关系。

例如某条Prompt相关为：

$$
I_{hw}=-1200,\qquad Q_{hw}=350
$$

软件得到：

$$
Z_P=-1200+j350
$$

后续模块可以直接用该复相关计算功率、相位、叉点积或码鉴别量。

### 3.7 默认环路分量

单分量信号使用唯一的数据分量。双分量信号保留数据与导频结果，但默认载波环和码环使用导频分量。

| 信号 | 分量0 | 分量1 | 默认环路分量 | 固定相位 |
|---|---|---|---:|---:|
| GPS L1 C/A | 数据 | 无 | 0 | 0 cycle |
| BDS B1I | 数据 | 无 | 0 | 0 cycle |
| GLONASS G1 | 数据 | 无 | 0 | 0 cycle |
| GPS L5 | L5I数据 | L5Q导频 | 1 | -0.25 cycle |
| BDS B2a | B2a数据 | B2a导频 | 1 | +0.25 cycle |
| Galileo E5a | E5a-I数据 | E5a-Q导频 | 1 | +0.25 cycle |
| Galileo E1 | E1B数据 | E1C导频 | 1 | +0.5 cycle |
| BDS B1C | B1C-D数据 | B1C-P导频 | 1 | +0.25 cycle |

选择默认环路分量只建立一组方便后续共用的VE/E/P/L/VL，不删除其他分量或副本。数据解调、双分量诊断和BOC双副本鉴别仍可访问完整相关矩阵。

### 3.8 固定载波相位统一

设默认环路分量的固定载波相位为$\phi_0$，该分量原始复相关为$Z$，统一到同相参考后的复相关为：

$$
Z'=Ze^{-j2\pi\phi_0}
$$

展开I、Q：

$$
\begin{aligned}
I'&=I\cos(2\pi\phi_0)+Q\sin(2\pi\phi_0)\\
Q'&=Q\cos(2\pi\phi_0)-I\sin(2\pi\phi_0)
\end{aligned}
$$

同一分量的VE/E/P/L/VL必须使用完全相同的旋转角度，保证载波环和码环使用一致的相位参考。

以GPS L5Q为例，固定相位为$-0.25$ cycle：

$$
\cos(-\pi/2)=0,\qquad \sin(-\pi/2)=-1
$$

因此：

$$
I'=-Q,\qquad Q'=I
$$

这次旋转同时作用于L5Q导频的VE/E/P/L/VL。L5I数据相关仍保持自己的原始分量相位，供独立数据处理使用。

### 3.9 PDI完整性

本节的“完整”只表示：这条1 ms相关结果可以与前后PDI连续组合，供后续相干积分、FLL、PLL、DLL和C/N0观察使用。PDI能被接收和记录，不等于它适合进入观察窗口。

一条PDI只有同时通过下列四类检查，才标记为完整。

| 检查类别 | 通过条件 | 检查目的 |
|---|---|---|
| 积分区间 | 当前结果覆盖完整的1 ms，不是移交后的首段残缺积分 | 防止把不同时长的相关值当成普通1 ms结果 |
| 输入数据 | 无样点缺口、无相关溢出、无命令迟到，并且必需的分量、副本和抽头结果均存在 | 确认当前复相关值可信 |
| 时间轴 | PDI历元、样点区间、主码周期号和1 ms片段号均与上一条连续 | 确认两条PDI之间没有丢失、重复或乱序 |
| 命令时间轴 | 当前命令号是软件已发出且尚在保留期内的命令，整条PDI均在该命令下形成 | 确认软件知道本PDI真正使用的NCO、抽头和分支配置 |

命令号正常变化不会自动使PDI失效。例如，PDI 100完整使用命令7，PDI 101从首样点开始完整使用已发出的命令8，两条PDI都可以是完整结果。只有命令号未知、倒退、迟到，或命令在一条PDI内部改变时，当前结果才不能用于连续观察。

`partial=true`表示移交后的首条结果不足1 ms。这是非整毫秒码相位移交后的正常现象，不是硬件故障。软件仍保留它的历元、样点数和错误状态，但不把它加入相干积分或任何连续观察窗口。

任意一类检查失败时，软件统一执行以下处理：

1. 保留当前PDI的时间和诊断信息；
2. 不用当前相关值更新任何观察或环路；
3. 清除依赖连续PDI的未完成积分和观察窗口；
4. 环路只按已经过去的真实时间继续预测或保持，不使用数0伪造一次测量；
5. 从下一条满足积分起点条件的完整PDI重新建立连续历史。

### 3.10 处理过程

本模块对每条PDI按以下顺序执行：

1. 检查PDI历元、错误标志和实际命令号；
2. 将载波步进解释为有符号物理频率；
3. 将首样点载波相位推进到PDI中心；
4. 复制样点、主码周期和1 ms片段时间轴；
5. 将全部有效复相关整数无损转换到浮点域；
6. 按信号目录选择默认闭环分量；
7. 对默认分量五抽头执行固定载波相位旋转；
8. 合并硬件标志、历元检查和命令检查，形成最终完整性；
9. 将统一软件PDI送入同步、积分和观察模块。

### 3.11 设计约束

- 软件不访问原始ADC I/Q样点；
- 硬件相关整数转换到浮点域时不改变数值尺度；
- PDI载波相位必须对应积分中心，而不是首样点；
- 默认环路分量选择不得删除或覆盖其他分量和副本；
- 同一分量的五个码抽头必须使用同一个固定载波相位旋转；
- 不完整PDI不得作为有效相关证据更新闭环观察窗口；
- 本模块不执行bit或二次码擦除；
- 本模块不形成频率、相位、码误差或C/N0观察；
- 本模块不更新载波环、码环、Monitor或状态机。
