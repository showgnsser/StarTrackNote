# 跟踪软件设计方案

## 软件接口记号

本文使用以下记号描述软件接口、物理量和时间范围。

| 记号 | 含义 |
|---|---|
| $Z=I+jQ$ | 一条复相关结果，$I$为同相分量，$Q$为正交分量 |
| `epoch` | 从1开始递增的1 ms PDI历元号 |
| `[first_epoch,last_epoch]` | 包含首尾历元的闭区间 |
| `ready` | 当前历元刚好形成了一个完整观察结果 |
| `valid` | 已形成的结果通过该模块的数值和质量检查 |
| `complete` | 当前PDI时间轴、硬件状态和命令确认均允许观察器消费 |
| chip | 码相位和码误差单位 |
| cycle | 载波相位单位；1 cycle等于一个完整载波周期 |
| Hz | 载波频率或频率误差单位 |
| Hz/s | 载波频率变化率单位 |

`ready`和`valid`必须分开解释。`ready=false`表示观察窗口尚未成熟；`ready=true, valid=false`表示窗口已经成熟，但结果没有通过门控。不能用数值0代替“尚未成熟”或“无效”。

本文所称PDI（Pre-Detection Integration，预检测积分）均指硬件形成的1 ms相关结果，不是20 ms CSV日志周期。软件每收到一条PDI执行一次`TrackEngine::processPdi()`。

## 1 设计范围

本文规定从1 ms硬件PDI进入软件开始，到软件生成下一条硬件控制命令为止的跟踪处理，包括：

1. PDI时间轴和命令确认；
2. PDI数值解码与默认环路分量选择；
3. 数据bit、覆盖码和导频二次码同步；
4. 1 ms结果的相干积分与非相干积累；
5. 载波频率、载波相位和码误差观察；
6. 载波FLL/PLL和载波辅助DLL控制；
7. C/N0、频率、相位、码环和动态监测；
8. 十一状态跟踪策略与状态切换；
9. 下一历元载波NCO、码NCO和相关抽头命令生成；
10. 当前历元观察、控制、状态和诊断结果输出。

本文不重复规定ADC、载波NCO、码NCO、本地码生成、相关器和1 ms累加的硬件实现，这些内容由[[09-逐模块定点化/18-跟踪逻辑定点化设计方案|跟踪逻辑定点化设计方案]]规定。软件不访问原始ADC I/Q样点，只消费`HwPdi`。

软件处理的唯一入口为：

```cpp
TrackResult TrackEngine::processPdi(const HwPdi& input,
                                    int8_t aid_symbol,
                                    bool aid_valid);
```

其中，`input`是当前1 ms硬件PDI；`aid_symbol`是与当前PDI对齐的可选已知导航符号，只能取`+1`或`-1`；`aid_valid`表示该符号及其时间映射可信。无外部符号辅助时，后两个参数分别为0和`false`。

软件输出为`TrackResult`。它同时保存当前历元形成的观察结果、环路状态、同步状态、监测结果、FSM状态，以及计划在下一1 ms边界生效的`HwCmd`。

### 1.1 当前源码口径

本文以`/home/showskills/SN770/Project/StarTrack`当前`codex/eight-signal-evolution`工作树为唯一实现依据。每个模块只描述当前已经存在的类、数据结构和调用顺序；后续设想和未接入算法不写成当前处理流程。

当前逻辑定点方案按资源池输出s18或s20相关值，当前软件`HwTap`仍使用`int32_t`保存s24范围内的相关整数。两者之间的现阶段接口关系为：逻辑输出先按符号扩展写入`HwTap`，数值本身不缩放，`PdiDecoder`仍按当前源码执行整数到`double`的无损转换。该接口事实不表示软件已经改成独立的s18/s20结构体。

## 2 跟踪软件数据链总览

`TrackEngine::processPdi()`严格按照六个阶段处理每条1 ms PDI。六个阶段的顺序是软件数据链的主线，后续各模块章节均从这条主线展开。

| 阶段 | 输入 | 处理 | 主要输出 |
|---:|---|---|---|
| 1 | `HwPdi`、预期历元、预期命令号 | 检查时间轴和错误标志，确认状态切换、码slew和E1稳定抽头命令 | `pdi_ok`、`cmd_ok`、命令确认结果 |
| 2 | `HwPdi`、信号目录 | 解码相关值和NCO参考，选择默认环路分量并完成固定相位对齐 | `PdiData` |
| 3 | `PdiData`、可选辅助符号 | 形成同步、C/N0、频率、相位、码误差及信号专属观察 | `SyncObs`、`FreqObs`、`PhaseObs`、`CodeObs`等 |
| 4 | 当前观察、上一历元环路状态 | 将观察重定时到控制历元，更新载波环和载波辅助码环 | `CarrierLoopResult`、`CodeLoopResult` |
| 5 | 监测结果、同步、C/N0和辅助有效性 | 更新十一状态FSM；满足切换条件时产生等待确认的目标状态 | `state`、`pending_state` |
| 6 | 当前状态、载波/码环输出、抽头策略 | 生成下一历元硬件命令并保存后续合法入口所需的物理锚点 | `HwCmd`、`TrackResult` |

处理链可以概括为：

```text
HwPdi
  -> 时间轴与命令确认
  -> PDI解码和环路分量选择
  -> 同步、积分和观察器
  -> 载波环与码环
  -> Monitor监测
  -> FSM策略选择
  -> 下一历元HwCmd
```

### 2.1 输入、内部数据和输出的分层

| 层级 | 代表类型 | 数值含义 | 允许的主要使用者 |
|---|---|---|---|
| 硬件输入 | `HwPdi` | 定点相关、实际命令号、NCO位字和硬件错误标志 | `PdiDecoder`、`TrackEngine`入口检查 |
| 软件PDI | `PdiData` | `double`复相关、物理Hz/cycle参考和软件完整性 | 同步、积分、观察器、C/N0 |
| 观察结果 | `FreqObs`、`PhaseObs`、`CodeObs` | 从一段PDI数据提取的测量量 | 环路、Monitor和诊断 |
| 环路结果 | `CarrierLoopResult`、`CodeLoopResult` | 连续控制状态和下一控制量 | 命令生成、Monitor和状态保存 |
| 监测结果 | `FreqStatus`、`PhaseStatus`、`DllStatus` | 多次独立观察形成的稳定性证据 | FSM、保护门和日志 |
| 状态策略 | `TrackState`、`TrackPolicy` | 当前相干长度、观察方法、更新周期和控制权限 | 观察器配置、环路门控、命令生成 |
| 硬件输出 | `HwCmd` | 下一历元NCO步进、可选相位装载、抽头和相关掩码 | 硬件寄存器接口 |

观察器、环路、Monitor和FSM的职责不能混合：

- Observer只从相关结果中提取测量；
- Loop保存连续控制状态并生成控制量；
- Monitor对多个观察或控制结果做稳定性判断；
- FSM只根据已经形成的证据选择策略；
- Logger只记录结果，不参与闭环。

### 2.2 每历元输出

每次`processPdi()`首先创建一个安全默认的`TrackResult`。只有对应模块在本历元真正形成结果时，相关字段才会置`ready=true`。因此一条输出中可以同时出现：频率观察成熟、码观察未成熟、同步仍在积累、环路只执行预测等不同状态。

`TrackResult`的主要字段如下。

| 字段 | 含义 |
|---|---|
| `freq`、`phase`、`code` | 本历元刚形成的载波频率、相位和码误差观察 |
| `sync`、`pilot_sync` | 数据bit或导频二次码同步状态 |
| `cn0`、`loop_cn0`、`display_cn0` | 控制、监测和显示用途的C/N0结果 |
| `carrier`、`code_loop` | 当前历元处理后的载波环和码环状态 |
| `state`、`pending_state` | 已确认状态和等待命令确认的目标状态 |
| `pdi_ok`、`cmd_ok` | 当前硬件时间轴和命令确认是否正常 |
| `freq_used` | 当前频率观察是否实际注入载波环 |
| `command`、`command_ready` | 下一历元硬件命令及其就绪标志 |

### 2.3 时间顺序

设当前输入为PDI $n$。当前源码的处理顺序为：

1. PDI $n$先报告它实际使用的`cmd_id`；
2. 软件用该命令号确认此前等待提交的状态或码控制事件；
3. 软件处理PDI $n$并更新观察器、环路和FSM；
4. 软件生成`apply_epoch=n+1`的新命令；
5. 下一条PDI用新的`cmd_id`回报命令是否按计划生效。

状态切换不能在“软件决定切换”的同一行直接视为完成。FSM先产生`pending_state`，软件把目标状态策略写入后续命令，只有后续PDI回报匹配的命令号后，状态才提交为`state_changed=true`。

## 3 PDI解码与默认环路分量选择

### 3.1 模块功能

软件入口的第一个数值处理模块由`PdiDecoder`和`LoopPdiSelector`组成。

`PdiDecoder`负责：

1. 将硬件相关整数无损转换为软件`double`；
2. 将u32载波步进换算成有符号物理频率；
3. 将PDI首样点载波相位推进到PDI中心；
4. 原样传递历元、命令、样点和主码分段时间轴；
5. 根据硬件错误标志形成第一层`complete`。

`LoopPdiSelector`负责：

1. 按信号目录选择默认闭环分量；
2. 将该分量的固定载波相位旋转到统一同相参考；
3. 将对齐后的VE/E/P/L/VL写入`PdiData`语义镜像；
4. 保留完整`corr[component][replica]`矩阵，不覆盖原始分量相位。

这两个模块不执行同步、不进行长积分、不计算频率或码误差，也不更新任何环路状态。

### 3.2 输入

输入类型为`HwPdi`。与本模块直接相关的字段如下。

| 输入字段 | 格式或类型 | 含义 |
|---|---:|---|
| `epoch` | `uint64_t` | 从1开始的1 ms PDI历元 |
| `cmd_id` | `uint64_t` | 本PDI实际采用的硬件命令号 |
| `first_sample` | `uint64_t` | 本PDI第一个ADC样点的绝对编号 |
| `sample_count` | `uint32_t` | 本PDI实际积分样点数 |
| `carrier_step` | u32位字 | 本PDI使用的载波NCO每样点步进 |
| `carrier_phase` | u32位字 | 本PDI首样点使用的载波NCO相位 |
| `code_period` | `uint64_t` | 从通道启动点累计的完整主码周期号 |
| `segment` | `uint8_t` | 当前主码周期内的1 ms片段号 |
| `segments_per_code` | `uint8_t` | 一个完整主码包含的1 ms片段数 |
| `partial` | `bool` | 当前PDI没有覆盖完整1 ms码区间 |
| `gap` | `bool` | 输入绝对样点时间轴不连续 |
| `overflow` | `bool` | 硬件相关累加发生数值溢出 |
| `cmd_late` | `bool` | 硬件命令晚于目标历元 |
| `corr[2][2]` | `HwCorr`矩阵 | 最多2个分量、2个副本，每项保存P/E/L/VE/VL复相关 |

### 3.3 输出

输出类型为`PdiData`。

| 输出字段 | 单位 | 来源或含义 |
|---|---:|---|
| `epoch`、`cmd_id` | 无 | 从`HwPdi`原样复制 |
| `first_sample`、`sample_count` | sample | 从`HwPdi`原样复制 |
| `code_period`、`segment` | 无 | 从`HwPdi`原样复制的主码时间轴 |
| `nco_hz` | Hz | 由u32载波步进按有符号频率换算 |
| `nco_phase` | cycle | 推进到PDI中心的载波NCO相位 |
| `corr[2][2]` | 软件相关尺度 | 全部分量、副本和五抽头的`double`复相关 |
| `prompt/early/late/very_early/very_late` | 软件相关尺度 | 选中默认环路分量并完成固定相位对齐后的语义镜像 |
| `complete` | 布尔 | 当前PDI是否允许进入后续观察器 |

### 3.4 载波步进换算

硬件`carrier_step`是模$2^{32}$的u32位字。软件先按32 bit二补码解释为有符号整数$K_c$：

$$
K_c=
\begin{cases}
R_c, & R_c<2^{31} \\
R_c-2^{32}, & R_c\ge 2^{31}
\end{cases}
$$

式中，$R_c$表示`carrier_step`的u32原始整数，$K_c$表示按有符号频率解释后的整数步进。

物理NCO频率为：

$$
f_{NCO}=\frac{K_c}{2^{32}}f_s
$$

式中，$f_{NCO}$表示当前PDI使用的载波NCO频率，单位Hz；$f_s$表示当前信号的固定采样率，单位sample/s。

### 3.5 PDI中心载波相位

硬件记录的是PDI首样点使用的载波相位。观察器需要统一使用PDI中心时刻，因此软件计算中心样点偏移：

$$
d_c=\frac{N-1}{2}
$$

式中，$N$表示`sample_count`，$d_c$表示从首样点到PDI样点中心的样点间隔；当$N=0$时源码令$d_c=0$。

首样点相位换算为cycle后，PDI中心相位为：

$$
\phi_{center}=\operatorname{frac}\left(
\frac{R_\phi}{2^{32}}+d_c\frac{K_c}{2^{32}}
\right)
$$

式中，$R_\phi$表示`carrier_phase`的u32原始整数；`frac`表示把结果回绕到$[0,1)$ cycle。

中心相位必须与`nco_hz`、`epoch`和当前PDI相关值一起传给后续相位恢复和NCO换字重定时模块。不能把首样点相位误写成PDI中心相位。

### 3.6 相关值解码

每个硬件复相关抽头包含有符号整数$I_{hw}$和$Q_{hw}$。当前源码直接执行：

$$
I_{sw}=\operatorname{double}(I_{hw}),\qquad
Q_{sw}=\operatorname{double}(Q_{hw})
$$

这里没有归一化、右移、除以积分样点数或幅度补偿。s24整数可以被IEEE 754双精度浮点无损表示，因此解码不改变相关值之间的幅度和相位关系。

例如硬件Prompt相关值为：

$$
I_{hw}=-1200,\qquad Q_{hw}=350
$$

解码后的软件复相关为：

$$
Z_P=-1200.0+j350.0
$$

后续观察器仍能使用同一数值计算功率、叉点积、相位和码鉴别量。

### 3.7 默认环路分量选择

单分量信号直接使用分量0。双分量信号保留数据和导频的完整相关矩阵，但当前默认载波环和码环使用导频分量1。

| 信号 | 分量0 | 分量1 | 默认环路分量 | 固定相位 |
|---|---|---|---:|---:|
| GPS L1 C/A | 数据 | 无 | 0 | 0 cycle |
| BDS B1I | 数据 | 无 | 0 | 0 cycle |
| GLONASS G1 | 数据 | 无 | 0 | 0 cycle |
| GPS L5 | L5I数据 | L5Q导频 | 1 | -0.25 cycle |
| BDS B2a | B2a数据 | B2a导频 | 1 | +0.25 cycle |
| Galileo E5a | E5a-I数据 | E5a-Q导频 | 1 | +0.25 cycle |
| Galileo E1 | E1B数据 | E1C导频 | 1 | +0.5 cycle |
| BDS B1C | B1C-D数据 | B1C-P导频 | 1 | +0.25 cycle |

设信号目录给出的固定分量相位为$\phi_0$，原始复相关为$Z$，对齐后的语义镜像为：

$$
Z'=Ze^{-j2\pi\phi_0}
$$

展开I、Q：

$$
\begin{aligned}
I'&=I\cos(2\pi\phi_0)+Q\sin(2\pi\phi_0)\\
Q'&=Q\cos(2\pi\phi_0)-I\sin(2\pi\phi_0)
\end{aligned}
$$

同一分量的VE/E/P/L/VL必须使用完全相同的旋转角度，避免载波环和码环看到不同的固定相位参考。

以GPS L5Q为例，固定相位为$-0.25$ cycle，因此：

$$
\cos(-\pi/2)=0,\qquad \sin(-\pi/2)=-1
$$

代入后得到：

$$
I'=-Q,\qquad Q'=I
$$

该旋转同时作用于L5Q导频的VE/E/P/L/VL。L5I数据分量仍保留在`corr[0][0]`中，不会被默认环路分量选择覆盖。

### 3.8 完整性处理

`PdiDecoder`首先根据硬件标志形成：

$$
complete_{decode}=\neg partial\land\neg gap\land\neg overflow\land\neg cmd\_late
$$

`TrackEngine`在解码和分量选择后，再合并软件检查：

$$
complete=complete_{decode}\land pdi\_ok\land cmd\_ok
$$

其中：

$$
pdi\_ok=(epoch=expected\_epoch)\land\neg gap\land\neg overflow\land\neg cmd\_late
$$

$$
cmd\_ok=(cmd\_id=expected\_cmd\_id)
$$

首条`partial=true`的PDI是非整毫秒码相位移交后的正常结果。它可以被记录，但`complete=false`，不能进入后续归一化观察器。`gap`、`overflow`和`cmd_late`属于硬件时间轴或数值故障；命令号不符合预期则令`cmd_ok=false`。

### 3.9 处理过程

本模块对每条PDI按以下顺序执行：

1. 读取硬件历元、命令号和错误标志，计算`pdi_ok`和`cmd_ok`；
2. 将u32载波步进解释为有符号频率；
3. 将首样点载波相位推进到PDI中心；
4. 复制样点、主码周期和1 ms片段时间轴；
5. 解码全部分量、全部副本和五个抽头的复相关；
6. 临时把分量0完整副本绑定到PDI语义镜像；
7. 按信号目录重新选择默认环路分量；
8. 对默认分量五抽头执行固定相位旋转；
9. 将硬件完整性与`pdi_ok/cmd_ok`合并为最终`complete`；
10. 把`PdiData`送入同步、积分和观察模块。

### 3.10 设计约束

- 软件PDI入口不访问原始ADC I/Q样点；
- 硬件相关整数转换为`double`时不改变数值尺度；
- `nco_phase`必须对应PDI中心，而不是首样点；
- 默认环路分量选择不得删除或覆盖完整`corr`矩阵；
- 五个码抽头必须使用相同的固定分量相位旋转；
- `complete=false`的PDI可以进入日志，但不得更新闭环观察器；
- 本模块不执行数据bit或导频二次码擦除；
- 本模块不形成频率、相位或码误差观察；
- 本模块不更新载波环、码环、Monitor或FSM。
